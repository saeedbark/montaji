# بنية مونتاجي

هذا الملف يشرح كيف تتصل أجزاء المشروع، لمن يريد أن يفهم الكود أو يساهم فيه. لطريقة التشغيل والاستخدام راجع [README](../README.md).

## الصورة العامة

مونتاجي جزءان:

1. **المحرر** (`public/`): صفحة ويب تعمل كلها في المتصفح. المشروع، المعاينة، والتصدير تجري هنا، وملفات المستخدم لا تغادر التبويب.
2. **الخادم المحلي** (`server/`): عملية Node.js صغيرة بلا مكتبات، لها ثلاث وظائف فقط: تقديم ملفات المحرر، حفظ مفتاح الذكاء الاصطناعي بعيداً عن المتصفح، وتشغيل خادم MCP.

```
                        ┌──────────────── المتصفح (تبويب المحرر) ────────────────┐
                        │                                                        │
 المستخدم ─── واجهة ───▶│  app.js ──▶ state (core.js) ──▶ render.js ──▶ Canvas   │
                        │     ▲              ▲                 │                 │
                        │     │              │                 └──▶ export.js ──▶ MP4
                        │  chat.js ──▶ agent.js (ينفّذ الأدوات)                   │
                        │     │   ▲          ▲                                   │
                        └─────┼───┼──────────┼───────────────────────────────────┘
                   /api/chat  │   │ الرد     │ نداء أداة عبر SSE (/api/bridge)
                        ┌─────▼───┴──────────┴──────── الخادم المحلي ────────────┐
                        │  chat.js (يضيف المفتاح)          bridge.js ◀── mcp.js  │
                        └─────┬──────────────────────────────────────────▲───────┘
                              ▼                                          │ /mcp
                     مزوّد الذكاء الاصطناعي                   عميل MCP خارجي
                  (Gemini / OpenAI / Claude…)               (Claude Code / Cursor…)
```

## المحرر (`public/js/`)

الملفات سكربتات كلاسيكية تُحمَّل بهذا الترتيب في `index.html`، وكل ملف يعتمد على ما قبله فقط:

| --- | --- | --- |
| `core.js` | `state`, `view`, `layout()`, `prop()` ودوال مساعدة | الحالة المشتركة: المشروع وموضع المؤشر، والإطارات المفتاحية (يُحمَّل في Node للاختبار) |
| `beats.js` | `Beats` | كشف BPM ومواضع الضربات من الموسيقى |
| `captiontools.js` | `CaptionTools` | الترجمة بلا واجهة: تحويل الكلمات إلى كتل، دمج وتقسيم وإعادة توقيت، SRT و VTT |

| `export.js` | `Exporter` | ترميز المشروع إلى MP4 عبر WebCodecs و mp4-muxer |
| `audiotools.js` | `AudioTools` | معالجة الصوت بلا واجهة: قص، توحيد المستوى، تلاشٍ، ترميز WAV و M4A |

| `chat.js` | — | لوحة المساعد، حلقة المحادثة، والجسر مع MCP |

### نموذج المشروع

المشروع كله كائن واحد اسمه `state` في `core.js`:

```js
state = {
  ratio: '16:9',
  clips:  [],  // المسار الرئيسي: صور ومقاطع فيديو متتابعة بلا فراغات
  overlays: [], // الطبقات فوق المسار الرئيسي: صور وفيديوهات بزمن بداية حر
  audios: [],  // الموسيقى والأصوات، توضع بحرية بزمن البداية
  texts:  [],  // النصوص فوق الفيديو، توضع بحرية بزمن البداية
  effects: [], // التأثيرات فوق الصورة (تحت النصوص)، توضع بحرية بزمن البداية
  captions: { lang, style, items: [] }, // الترجمة: نمط واحد وكتل متتالية بتوقيت كلماتها
  sel: null,   // العنصر المحدد { kind, id }
}
```

ترتيب الرسم في `Render.frame`: المسار الرئيسي (مع الانتقالات) ← الطبقات بترتيب `track` ← التأثيرات ← النصوص ← الترجمة.

- **التأثيرات المربوطة:** التأثير الذي فيه `at` (معرّف مقطع) يحسب `layout()` موضعه من المقطع في كل مرة: `atMode: 'cut'` متمركز على لحظة دخول المقطع، و`'clip'` يغطي المقطع كله. لهذا يبقى التكبير الضبابي على القطع بعد `sync_to_beat` أو إعادة الترتيب. تحريك التأثير يدوياً يفك الربط.
- **رسم التأثيرات** في `Render.frame` بعد المقطع وقبل النصوص: تُنسخ الصورة المركّبة إلى لوحة مؤقتة ثم تُرسم من جديد بالتأثير. شدّة التأثير عبر مدته يحددها `shape` في `Render.EFFECTS` (ذروة في المنتصف، ثابت، أو تصاعد).

- **المقاطع متتابعة:** لا يُخزَّن زمن بداية المقطع، بل يحسبه `layout()` من ترتيب المقاطع وأطوالها (`_start`). طول المقطع `(out - in) / speed`.
- **الإحداثيات نسبية:** موضع النص `x` و `y` من 0 إلى 1، وحجمه نسبة من ارتفاع الإطار، فتبقى النتيجة واحدة في كل الدقات والمقاسات.
- **التراجع:** `pushHist()` في `app.js` يحفظ نسخة من `state`، و`commit()` يسجّل خطوة بعد أي تعديل.

### الطبقات (`state.overlays`)

- **العنصر** يُبنى بدوال `make` نفسها التي تبني المقاطع ثم يحوّله `asOverlay()` في `app.js`، فيحمل `type` (`image` أو `video`) و`el` و`file` كالمقطع، ومعها `start` و`track` (الصف، الأعلى يُرسم فوق) و`x` و`y` (المركز، نسبي) و`scale` (العرض نسبةً إلى عرض الإطار، والارتفاع يتبع أبعاد الوسيط) و`rot` و`opacity` والقناع والإطار والمزج.
- **المدة:** `layout()` يمدّ `view.total` إلى نهاية آخر طبقة، و`view.main` نهاية المسار الرئيسي. بعدها تبقى الخلفية سوداء (`Render.frame` لا يرسم مقطعاً، و`syncMedia` يوقف آخر فيديو).
- **الرسم** في `drawOverlay()`: مع قناع يُرسم الشكل بظله ثم تُقص الصورة داخله؛ بلا قناع يتبع الظل شفافية الصورة نفسها (شعار PNG). الهندسة المرسومة تُخزَّن في `_g`، ومنها `Render.overlayHit()` يعرف ما تحت المؤشر (تحريك، زاوية تكبير، مقبض تدوير)، فمقابض المعاينة تطابق ما رُسم حتى مع الإطارات المفتاحية وحركة الدخول.
- **فيديو الطبقات:** لكل طبقة عنصر `<video>` خاص. `syncOverlays()` يشغّل ويوقف وينقل الفيديوهات الظاهرة عند المؤشر (أربعة معاً على الأكثر في المعاينة)، و`prepareFrame()` في التصدير ينقل كل الظاهر منها بـ`seekExact` بالتوازي، و`mixAudio()` يمزج صوت غير المكتوم منها.
- **التنقل بين المسارين:** `toOverlay()` و`toMain()` ينقلان العنصر بوسيطه نفسه (بلا إعادة تحميل الملف).

### الترجمة (`state.captions`)

- **النموذج:** `{ lang, style, items }`. الكتلة `{ id, start, end, text, words: [{ w, t0, t1 }] }` بزمن المشروع. كتلة واحدة تظهر في كل لحظة (صف واحد بلا تداخل)، والنمط واحد لكل الكتل.
- **التفريغ** (`Captions.transcribe()`): الصوت يؤخذ من مزج التصدير نفسه (`Exporter.mixAudio`) أو من ملف العنصر المحدد، يُحوَّل إلى أحادي 16 كيلوهرتز (`AudioTools.toMono16k`) ويُقطَّع أجزاء متداخلة تحت حد المزوّد (`sttChunks`)، ويُرسل كل جزء WAV إلى `/api/transcribe`. كلمات الأجزاء تُدمج بلا تكرار (`mergeChunks`)، تُزاح إلى زمن المشروع مع سرعة المقطع (`place`)، ثم `toItems()` يقطعها كتلاً عند علامات الترقيم والسكتات وحد الأحرف والمدة.
- **الخادم** (`server/stt.js`): نوعان من المزوّدين. `whisper` يخاطب `/audio/transcriptions` بصيغة `verbose_json` وتوقيت الكلمات (OpenAI، Groq، أو خادم محلي عبر `STT_BASE_URL`). `chat` يرسل الصوت إلى نموذج محادثة (Gemini) ويطلب JSON بالجمل وتوقيتها؛ التوقيت تقريبي وتوقيت الكلمات يُوزَّع داخل الجملة بنسبة أطوالها (`spread`). الرد يُفحص رقماً رقماً قبل إعادته.
- **تمييز الكلمة في العربية** (`drawCaptions()`): الحروف تتصل فلا تُرسم الكلمة وحدها. يُرسم السطر كاملاً، ثم يُعاد رسمه بلون التمييز داخل مستطيل الكلمة فقط (`clip`). موضع الكلمة يُحسب بقياس ما قبلها في سطرها، من اليمين في RTL. «الكلمة المكبّرة» ترسم السطر بلا الكلمة ثم الكلمة مكبّرة حول مركزها، و«كلمة كلمة» يقص السطر عند آخر كلمة نُطقت. السطر الذي يخلط العربية بكلمات لاتينية يعيد المتصفح ترتيبه، فقد يقع التمييز فيه على موضع غير دقيق.
- **التعديل لا يغيّر في المكان:** `retime` و`setText` و`merge` و`splitAt` تعيد كتلاً جديدة بمصفوفة `words` جديدة، فتبقى لقطات سجل التراجع سليمة.

### الإطارات المفتاحية (`item.kf`)

- **النموذج:** `item.kf = { x: [{ t, v, e }], opacity: [...] }`. `t` نسبي من بداية العنصر بزمن الخط الزمني، فيبقى صحيحاً حين يتحرك العنصر أو يُعاد ترتيب المقاطع. `e` انسيابية الانتقال إلى الإطار التالي: `smooth` | `linear` | `hold`.
- **القراءة من دالة واحدة:** `prop(item, key, lt)` في `core.js` تعيد قيمة الإطارات إن وُجدت وإلا القيمة الثابتة. `render.js` و`syncMedia` و`audioGain` و`mixAudio` كلها تقرأ الخصائص المتحركة بها. الخصائص المسموحة ومداها لكل نوع في `KF_PROPS` (ونسخة منها في `projecttools.js` لأنه يُحمَّل وحده في Node).
- **الكتابة لا تغيّر في المكان:** `setKey` و`removeKey` و`moveKeys` وغيرها تضع كائن `kf` جديداً، فلقطات التراجع (نسخ سطحية للعناصر) لا تتأثر. `setVal()` يكتب إطاراً عند المؤشر إن كانت الخاصية متحركة وإلا القيمة الثابتة، وتستعمله اللوحة والسحب في المعاينة.
- **التقسيم:** `splitKf()` يوزّع الإطارات على الجزأين ويضيف إطاراً عند نقطة القطع بالقيمة المحسوبة. المقطع المقطوع يصير خطياً في جزأيه كي تتطابق القيمة عند القطع (الناعم يصبح تقريبياً هناك). `splitItem()` في `app.js` هو مسار التقسيم الوحيد للواجهة وللأداة `split`.
- **المقطع الرئيسي:** `zoom` و`panX` و`panY` تُطبَّق فوق الملاءمة، وإطاراتها تعطّل حركة الكاميرا الجاهزة (`motion`). `opacity` تمزج المقطع مع الأسود.
- **الصوت في التصدير:** الخاصية المتحركة `volume` تُحوَّل إلى منحنى واحد (50 نقطة في الثانية) يجمع الإطارات والتلاشي ويُطبَّق بـ`setValueCurveAtTime`.
- **الواجهة:** `kslider()` يرسم شريط الخاصية وزر ◇، و`syncKfInputs()` يحدّث الأشرطة حين يتحرك المؤشر دون إعادة بناء اللوحة. وحدات الأدوات (نسب مئوية) تُحوَّل في جدول `KF_API` في `agent.js`.

### المعاينة والتصدير يشتركان في الرسم

`Render.frame(ctx, W, H, t)` يرسم الإطار عند الزمن `t` على أي Canvas بأي حجم. المعاينة تستدعيه في كل `requestAnimationFrame`، والتصدير يستدعيه لكل إطار بالدقة الكاملة ثم يرمّزه بـ`VideoEncoder`. لهذا ما تراه في المعاينة هو ما يخرج في الملف، وأي مؤثر جديد يُكتب مرة واحدة في `render.js`.

التصدير ليس تسجيلاً للشاشة: كل إطار يُحضَّر (`seekExact` للفيديو) ثم يُرسم ويُرمَّز، والصوت يُمزج دفعة واحدة في `OfflineAudioContext`.

### `app.js` و `window.studio`

`app.js` أكبر ملف، وأقسامه معلّمة بتعليقات `/* ===== … ===== */`: الإشعارات، التراجع، الاستيراد، مزامنة التشغيل، الخط الزمني، عمليات التحرير، لوحة الخصائص، التصدير، المثال الجاهز، ثم ربط الأزرار. في آخره يصدّر واجهة صغيرة `window.studio` (مثل `refresh`, `commit`, `setTime`, `addFiles`, `exportVideo`) هي كل ما يستخدمه المساعد من الواجهة.

### الخط الزمني يبني الظاهر فقط

`renderTimeline()` يعيد بناء HTML الخط الزمني عند كل تعديل، لكنه لا يبني إلا العناصر والعلامات الواقعة في الجزء الظاهر وعرض شاشة قبله وبعده (`tlWin`)، ومستمع `scroll` يعيد البناء حين يقترب الظاهر من حافة هذه النافذة. الصفوف وارتفاعاتها تُحسب من كل العناصر. لهذا **لا تفترض أن كل عنصر له عقدة في DOM**: ابحث عنه بـ`data-id` وتعامل مع غيابه. مؤشر التشغيل يتحرك بـ`transform`، و`loop()` يقرأ موضع التمرير من `tlView` لا من العنصر، كي لا يفرض إعادة تخطيط في كل إطار.

### استوديو الصور

نافذة مستقلة عن الخط الزمني، لها حالتها وسجل تراجعها الخاص (نسخ كاملة من الصورة، ست خطوات على الأكثر). التعديلات التي تغيّر البكسلات (قص، تدوير، حجم، إزالة خلفية) تُطبَّق فوراً على لوحة العمل، أما الفلتر والألوان ولون الخلفية الجديدة فتُدمج عند الحفظ فقط.

- **الفصل بين المنطق والواجهة:** `imagetools.js` لا يعرف شيئاً عن النافذة، ودواله التي تعمل على البكسلات تقبل أي كائن `{ data, width, height }`، ولهذا تُختبر في Node (`test/imagetools.test.js`).
- **إزالة الخلفية لونية:** تُستخرج الألوان الغالبة على إطار الصورة، يُصنَّف كل بكسل بحسب بعده عنها، ثم تمتد تعبئة من الحواف (أو من نقطة النقر) عبر البكسلات القريبة، وتتبع التدرّج الهادئ. لا يوجد نموذج ذكاء اصطناعي، التزاماً بمبدأ «بلا مكتبات».
- **الترميز متزامن** عبر `toDataURL` لأنه يعمل والصفحة في الخلفية (نداء عبر MCP)، بعكس `toBlob`.
- **الدمج:** `ImageTools.mergeLayout()` حساب بحت يعيد موضع كل صورة والجزء المأخوذ منها، فيُختبر في Node. المعاينة ترسم نسخاً مصغّرة (ألف بكسل) على التخطيط نفسه، والناتج النهائي يُرسم صورةً صورة بالدقة الكاملة فلا تجتمع كل الصور الكبيرة في الذاكرة. الحد الأقصى 8192 بكسل للضلع و40 ميغابكسل، ويُصغَّر كل شيء بالنسبة نفسها إن تجاوزها. الأداة `merge_images` تستخدم `ImageTools.merge()` على صور المقاطع مباشرة.
- **العودة إلى المشروع:** `ImageStudio.setClipImage()` يضع لوحة Canvas مكان صورة المقطع (`el`, `w`, `h`, `thumb`). الصورة القديمة تبقى في لقطات سجل التراجع، فيعمل «تراجع» كالمعتاد. الأداة `edit_image` تستخدم الدالة نفسها.

### تحويل الفيديو إلى صوت

- **فك الصوت** بـ`decodeAudioFile()` نفسها التي يستخدمها التصدير: المتصفح يقرأ صوت حاوية الفيديو مباشرة ويعيد عيّناته بتردد 48 كيلوهرتز.
- **المعالجة** في `AudioTools.process()`: قص المدى، خفض ما زاد على قناتين إلى ستيريو، توحيد المستوى إلى -1 dBFS، وتلاشٍ خطّي. تعمل على أي كائن يشبه `AudioBuffer`، فتُختبر في Node (`test/audiotools.test.js`).
- **الترميز:** WAV يُكتب يدوياً (16 بت). M4A هو AAC عبر `AudioEncoder` داخل حاوية MP4 من mp4-muxer نفسها، بلا مسار فيديو. إن لم يدعم المتصفح AAC يُعطَّل خيار M4A ويُستخدم WAV. لا MP3 لأن ترميزه يحتاج مكتبة.
- **الإضافة إلى المشروع** تمرّ بـ`studio.addFiles()` بملف WAV (بلا فقدان، ويُفك فوراً)، ثم يُضبط موضعه: إن جاء من مقطع بسرعته العادية يوضع حيث يُسمع المقطع نفسه، فيبقى متزامناً. الإضافة والكتم خطوة تراجع واحدة. الأداة `extract_audio` تستخدم `AudioExtract.addToProject()` نفسها.

### تقسيم الفيديو

- **النسخ المباشر (MP4/MOV):** `VideoTools.parseMp4()` يقرأ صندوق `moov` وحده (لا الملف كله) ويحوّل جداول العيّنات (`stsz` `stco`/`co64` `stsc` `stts` `ctts` `stss`، وقائمة التعديل `elst`) إلى مصفوفات لكل عيّنة. `copyPart()` يقرأ بايتات عيّنات الجزء من الملف دفعات (`Blob.slice`) ويمرّرها كما هي إلى mp4-muxer عبر `addVideoChunkRaw` و`addAudioChunkRaw`، مع `avcC`/`hvcC` و AudioSpecificConfig الأصلية. لا فك ولا ترميز، فالتقسيم سريع وبلا فقدان.
- **المحاذاة:** الجزء يجب أن يبدأ بإطار مفتاحي، فيقع القطع عند الإطار المفتاحي السابق. في وضع «كل مدة» يُقاس كل جزء من البداية الفعلية للجزء الذي قبله، فلا يزيد جزء على المدة المطلوبة. الصفر في الملف الناتج هو زمن فك الإطار المفتاحي (مع إطارات B يُفك قبل عرضه)، ويبدأ الصوت من الزمن نفسه، لأن كل مسار في MP4 بلا قائمة تعديل يبدأ من صفر؛ فيبقى التزامن بدقة إطار صوت واحد.
- **الحالات الأخرى** (WebM، MP4 مجزّأ، ترميز صوت غير AAC، أو حين يختار المستخدم «قطع دقيق»): إعادة ترميز في `splitvideo.js`، كل إطار بـ`seekExact` ثم `VideoEncoder` (الإعدادات من `Exporter.pickVideoConfig`)، والصوت من `decodeAudioFile()`.
- الأجزاء تُصنع واحداً بعد الآخر وتُسلَّم فوراً (تنزيل في النافذة، أو `/api/export/save` للأداة `split_video_file`)، فلا تجتمع كلها في الذاكرة.
- **الإضافة إلى المشروع** (`VideoSplit.addToProject()`) لا تصنع ملفات: يُضاف الملف مرة واحدة ثم يُنسخ المقطع بـ`cloneItem` لكل جزء مع `in`/`out` مختلفين، فالقطع دقيق ولا يتكرر الملف في الذاكرة. إن فُتحت النافذة من مقطع في المشروع تحلّ الأجزاء محله في مكانه.
- **الاختبار:** `test/videotools.test.js` يبني ملفات MP4 مصطنعة بإطارات B وصوت AAC بمكتبة mp4-muxer نفسها، ثم يتحقق من القراءة والمحاذاة ومن أن كل جزء يحمل البايتات الصحيحة متزامنة.

### ملف المشروع (`.montaji`)

أرشيف ZIP بلا ضغط: `project.json` (الخط الزمني) ومجلد `media/` فيه ملفات الوسائط كما هي.

- **الحقول المركّبة** اثنان فقط، ولكل منهما معالجة صريحة في `serialize()` و`normalize()`: `kf` في العناصر، و`captions` (نمط وكتل بكلماتها).
- **الحفظ:** `ProjectTools.serialize()` يأخذ من كل عنصر حقوله البسيطة فقط (أرقام ونصوص ومنطقيات)، ويترك كائنات المتصفح وما يُشتق من الملف عند الفتح (`el`, `url`, `thumb`, `buf`, `srcDur`…). فأي خاصية جديدة تُضاف إلى العناصر تُحفظ تلقائياً. العناصر التي تشترك في الملف نفسه (بعد تقسيم أو تكرار) تشير إلى وسيط واحد. صورة عُدّلت في استوديو الصور مصدرها لوحة Canvas، فتُحفظ PNG.
- **بلا نسخ في الذاكرة:** `zipParts()` يعيد أجزاء تُجمع بـ`new Blob(parts)`، والملفات فيها مراجع إلى ملفات القرص. كل ملف يُقرأ مرة واحدة دفعات لحساب CRC. ZIP64 يُستعمل حين يتجاوز ملف أو الأرشيف 4 غيغابايت.
- **الفتح:** `readZip()` يقرأ فهرس الأرشيف من آخره فقط، وكل وسيط شريحة (`Blob.slice`) من ملف المشروع. ثم `studio.loadProject()` يبني العناصر بدوال `make` نفسها التي يستعملها الاستيراد، ويستبدل الحالة خطوةَ تراجع واحدة.
- **الملف غير موثوق:** `normalize()` يفحص كل قيمة قبل دخولها الحالة: أرقام ضمن مداها، قيم من قوائم معروفة، ألوان ومعرّفات بصيغتها الدقيقة، وما لا يُعرف يُهمل. هذا ضروري لأن بعض الحقول (اللون، المعرّف) تدخل في HTML الواجهة بلا تهريب. **أي خاصية جديدة للعناصر لا تعود عند الفتح حتى تُضاف إلى `specs()`** في `projecttools.js`.
- الأداتان `save_project` و`open_project`: الحفظ مع `save_as` يمرّ بـ`/api/project/save` إلى مجلد `projects/`، والفتح عبر MCP فقط لأن الخادم هو من يقرأ الملف بمساره (رابط مؤقت كما في `import_media`).

## المساعد الذكي

المساعد لا يكتب فيديو، بل **يستدعي أدوات** تعدّل `state`، تماماً كما يفعل المستخدم بالفأرة.

1. `chat.js` يرسل المحادثة وتعريفات الأدوات إلى `/api/chat`.
2. `server/chat.js` يضيف المفتاح من `.env` ويمرّر الطلب إلى المزوّد بصيغة OpenAI Chat Completions (كل المزوّدين يوفّرون نقطة متوافقة معها، فلا يوجد كود خاص بكل مزوّد).
3. إن ردّ النموذج بنداءات أدوات فـ`chat.js` ينفّذها عبر `Agent.run(name, args)` ويعيد النتائج إليه، وتتكرر الحلقة حتى يرد بنص.
4. `Agent.flush()` يسجّل كل تعديلات الدور خطوة تراجع واحدة.

**تعريف الأداة وتنفيذها منفصلان:** `tools.js` يصف الأداة (اسم، وصف، مخطط JSON)، و`agent.js` ينفّذها في دالة بالاسم نفسه داخل `impl`. الملف `tools.js` وحده مشترك بين المتصفح والخادم، وينتهي بـ`module.exports` المشروط لهذا السبب.

## خادم MCP والجسر

عميل MCP يتصل بالخادم، لكن المشروع يعيش في تبويب المتصفح. الجسر (`server/bridge.js`) يصل بينهما:

```
عميل MCP ── POST /mcp (tools/call) ──▶ mcp.js ──▶ bridge.callBrowser()
                                                        │  SSE: {id, name, args}
                                                        ▼
                                          تبويب المحرر: Agent.run(name, args)
                                                        │
عميل MCP ◀── النتيجة ◀── mcp.js ◀── POST /api/bridge/result {id, result}
```

- التبويب يفتح اتصال SSE دائماً على `/api/bridge`؛ آخر تبويب فُتح هو الذي يستقبل النداءات.
- كل نداء له `id` ووعد معلّق في `pending` يكتمل عند وصول النتيجة أو تنتهي مهلته.
- `import_media` و`open_project` هما الأداتان اللتان يشارك الخادم في تنفيذهما: المتصفح لا يقرأ ملفات الجهاز بمسارها، فالخادم يمنح كل ملف رابطاً مؤقتاً (`/api/media/<token>`) يُقرأ مرة واحدة.
- الخادم بلا جلسات (Streamable HTTP)، ويدعم `initialize` و `ping` و `tools/list` و `tools/call`.

## الخادم (`server/`)

| الملف | الوظيفة |
| --- | --- |
| `index.js` | ينشئ خادم HTTP ويوزّع الطلبات |
| `config.js` | المسارات، قراءة `.env` عند كل طلب، قائمة المزوّدين |
| `http.js` | أنواع الملفات، `trusted()`، وتقديم ملفات `public/` بثّاً من القرص مع `ETag`/304 و`Range` |
| `chat.js` | `/api/chat` |
| `settings.js` | `/api/settings/key`: يكتب مفتاح المزوّد الذي اختاره المستخدم في `.env` (مع `AI_PROVIDER`)، بقائمة مزوّدين ثابتة ومفتاح بلا مسافات أو أسطر كي لا يُحقن متغيّر آخر في الملف، وكتابة ذرّية. لا يعيد المفتاح أبداً |
| `stt.js` | `/api/transcribe`: يستقبل WAV، يضيف مفتاح خدمة التفريغ من `.env`، ويعيد `{ segments, words }` |
| `bridge.js` | `/api/bridge` و `/api/bridge/result` و `/api/media/*` |
| `exports.js` | `/api/export/save` و`/api/captions/save` و`/api/project/save`: تحفظ فيديو مصدَّراً أو ملف ترجمة في `exports/`، أو ملف مشروع في `projects/` (اسم منقّى، بلا مسارات، ولا يكتب فوق ملف) |
| `mcp.js` | `/mcp` |

### حدود الأمان

هذه الضمانات مقصودة ومغطاة بالاختبارات في `test/server.test.js`؛ حافظ عليها عند أي تعديل:

- **الاستماع على `127.0.0.1` فقط**، فلا يصل إلى الخادم جهاز آخر في الشبكة.
- **`trusted()`** يرفض أي طلب `/api` أو `/mcp` ترويسة `Host` أو `Origin` فيه ليست العنوان المحلي، كي لا يستعمل موقع تزوره مفتاحك أو يتحكم بمحررك.
- **الملفات الثابتة من `public/` فقط.** الخادم و`.env` خارج هذا المجلد، وفحص المسار يجري على المسار الناتج بعد الدمج لا على نص الرابط، وتُرفض الملفات المخفية.
- **المفتاح لا يغادر الخادم:** `/api/config` يعيد اسم المزوّد والنموذج فقط (للمساعد ولخدمة التفريغ).
- **مفتاح كل خدمة يذهب إليها وحدها:** مع `STT_BASE_URL` (خادم تفريغ مخصّص) لا يُرسل إلا `STT_API_KEY`، لا مفتاح OpenAI أو غيره.

## الاختبارات

`npm test` يشغّل `node --test` (مُشغِّل Node المدمج، بلا مكتبات):

- `test/config.test.js`: تحليل `.env` واختيار المزوّد.
- `test/tools.test.js`: سلامة تعريفات الأدوات، وأن لكل أداة تنفيذاً.
- `test/imagetools.test.js`: إزالة الخلفية على صور مصطنعة، تخطيط دمج الصور، وسلامة بنية ملف ZIP.
- `test/audiotools.test.js`: قص الصوت وتوحيده وتلاشيه، وبنية ملف WAV.
- `test/videotools.test.js`: مواضع القطع، قراءة MP4، ونسخ أجزائه بلا إعادة ترميز مع بقاء الصوت متزامناً.
- `test/projecttools.test.js`: كتابة ZIP وقراءته (ومنه ZIP64 والملفات التالفة)، حفظ الملف المشترك مرة واحدة، ورفض القيم غير الآمنة عند الفتح.
- `test/projectfeatures.test.js`: حفظ الطبقات والترجمة والإطارات المفتاحية وفتحها، ومشاركة الملف بين طبقة ومقطع، ورفض قيمها غير الآمنة.
- `test/captiontools.test.js`: تقطيع الكلمات إلى كتل، الدمج والتقسيم وإعادة التوقيت، دمج أجزاء الصوت الطويل، وصيغتا SRT و VTT.
- `test/keyframes.test.js`: `prop()` بكل انسيابية، التعديل بلا تغيير في المكان، التقسيم مع حفظ القيمة عند القطع، و`layout()` مع طبقة تتجاوز المسار الرئيسي.
- `test/stt.test.js`: اختيار خدمة التفريغ من `.env`، قراءة ردود المزوّدين، وتجهيز الصوت (أحادي 16 كيلوهرتز، التقطيع).
- `test/server.test.js`: يشغّل الخادم على منفذ حر ويختبر الملفات الثابتة، محاولات تجاوز المجلدات، فحص المصدر (ومنه `/api/transcribe`)، حفظ الملفات، وبروتوكول MCP.

كود المتصفح (الرسم، التصدير، الخط الزمني) يُختبر يدوياً حالياً. إضافة اختبارات له مساهمة مرحّب بها.
